# Expo / Metro Bundling Artifacts

Generated by `npm run mobile:start` (from project root)
→ `expo start` in `mobile/`

This covers the Metro bundler running as a **dev server** — the mode used
during all local development with `expo run:ios --no-bundler` and
`expo run:android --no-bundler`. Metro serves the JS bundle over the network;
nothing is written to the project as a compiled bundle.

For production/export bundling (`expo export`, `dist/` output), see the
"Production export" section below.

---

## Dev server mode (`expo start` / Metro)

### `$TMPDIR` — entirely outside iCloud scope

Metro keeps all of its runtime caches in `$TMPDIR`
(`/var/folders/sm/…/T/` on this machine). None of these files are inside
iCloud Drive and none require exclusion management.

| File / pattern | What it is |
|---|---|
| `metro-file-map-<hash>` | Metro's hasteFS file map — a single binary blob (~5 MB) rebuilt when the watched file tree changes. Treated as opaque data by Metro. |
| `metro-transform-cache-…/` | Hermes/Babel transform output cache — one entry per transformed source file, keyed by content hash. Avoided on cache hit; re-created on invalidation. |
| `metro-bundler-…/` | In-memory bundle state spilled to disk for hot reload continuity. |

### `mobile/.expo/` — inside iCloud scope, inside the project

Small directory; covered by `flag-temp-files.sh` and the Watchman trigger.

| File | Written by | What it is |
|---|---|---|
| `xcodebuild.log` | `expo run:ios` | Full Xcode build stdout; overwritten each build. Can grow to tens of MB. |
| `xcodebuild-error.log` | `expo run:ios` | Xcode stderr; overwritten each build. |
| `devices.json` | `expo start` | Simulator/device state cached by Expo CLI for the current session. |
| `prebuild/cached-packages.json` | `expo prebuild` | Manifest of packages processed during last prebuild run. |
| `web/cache/production/images/…/*.png` | `expo start --web` | Resized icon and splash-screen PNGs generated from `app.json` assets. Written once per asset hash; not regenerated unless assets change. |
| `README.md` | Expo CLI | Static doc file; not build output. |

### `node_modules/.cache/` — not present

Metro does **not** write a transform cache into `node_modules/.cache/` in this
project's configuration. All transform output goes to `$TMPDIR`. No exclusion
action needed.

## Production export (`expo export` / `dist/`)

Not currently wired into any npm script, but noted for completeness.
`expo export` compiles the JS bundle to disk for static hosting or OTA updates.

| Location | Extension | What it is |
|---|---|---|
| `dist/_expo/static/js/` | *(none — content-hash filenames)* | Compiled JS bundle, split by platform |
| `dist/_expo/static/js/` | `.map` | Source maps for the compiled bundle |
| `dist/_expo/static/js/` | `.hbc` | Hermes bytecode — only if Hermes compilation is enabled for the export |
| `dist/assets/` | varies | Static assets (images, fonts) copied from the project |
| `dist/` | `.html` | Web entry point (web platform only) |
| `dist/` | `.json` | Expo update manifest |

`dist/` is already covered by `flag-temp-files.sh`'s
`apply_all_icloud "${PROJECT}/dist"`.

---

## Hermes compiler cache — `~/Library/Caches/` (outside iCloud scope)

When Hermes compiles JS to bytecode (production builds only), it uses a
content-addressed compiler cache in `~/Library/Caches/`. This location is
outside iCloud Drive scope and covered by no flag-temp-files.sh entry, but
it does not need one — `~/Library` is never synced to iCloud Drive.

## Exclusion coverage gaps

| Location | Gap | Recommendation |
|---|---|---|
| `mobile/.expo/web/cache/` | `.png` files are written here whenever `expo start --web` runs or asset hashes change. Covered by the `.expo/**` Watchman trigger and `flag-temp-files.sh`. | No action needed; already covered. |
| `$TMPDIR/metro-…` | Outside iCloud scope entirely. | No action needed. |
| `dist/` | Covered by `flag-temp-files.sh` at postinstall time. | Add `"predist": "bash scripts/flag-temp-files.sh"` if an `expo export` script is added in future. |

## Comparison: dev server vs. production export

| Artifact | Dev server (`expo start`) | Production export (`expo export`) |
|---|---|---|
| JS bundle | Served from memory by Metro; never written to project | Written to `dist/_expo/static/js/` |
| Source map | Served in-memory | Written to `dist/_expo/static/js/*.map` |
| Hermes bytecode | Not produced | Written to `dist/` if enabled |
| Transform cache | `$TMPDIR` only | `$TMPDIR` only |
| Metro file map | `$TMPDIR` only | `$TMPDIR` only |
| Project-local writes | `mobile/.expo/` only | `mobile/.expo/` + `dist/` |
| iCloud exposure | Minimal | Moderate (`dist/` until flagged) |
