## Example price points

- **Workers Paid, our scale:** $5/mo base. At ~26M requests/mo (avg ~10 req/s; peak <100 req/s): (26M − 10M) × $0.30/M = **$4.80** requests + ~52M CPU-ms (2 ms avg) → (52M − 30M) × $0.02/M = **$0.44** ⇒ **≈ $10.25/mo** — *but only if the app were rewritten for Workers; the Express monolith won't run as-is.*
- **Containers always-on (basic: 1/4 vCPU, 1 GiB, 4 GB disk), 730 h/mo:** memory (730 − 25 incl.) GiB-h = 2.538M GiB-s × $0.0000025 ≈ **$6.35**; disk (2,920 − 200) GB-h = 9.79M GB-s × $0.00000007 ≈ **$0.69**; active vCPU at light load (~10% of ¼ vCPU) ≈ 65.7k vCPU-s − 22.5k incl. ≈ **$0.86**. Total ≈ **$7.90 overage + $5 base ≈ $13/mo** for an always-on Express container (Postgres still external).
- **R2, 50 GB photos:** (50 − 10 free) × $0.015 = **$0.60/mo** storage; typical ops within free tier (1M Class A / 10M Class B); egress **$0.00** at any download volume.
- **TLS + CDN + WAF:** **$0/mo** (Free plan, Universal SSL, proxied DNS). Load Balancing add-on **$5/mo** only if multi-origin failover is ever needed.

## Fit assessment

- **The Express monolith does not map cleanly onto Cloudflare alone.** Workers' request-scoped isolate model cannot host a long-lived Node process with in-process `setInterval` schedulers, and Cloudflare has no VM product and **no managed PostgreSQL 16** — two of the three core workload pieces are missing or require rework.
- **Cloudflare Containers (GA April 2026) is the one honest lift-and-shift path on-platform:** an always-on `basic` instance runs the Express app with its schedulers intact for roughly **$13/mo all-in** (active-CPU billing keeps idle cost low). Caveats: disk is ephemeral, instances can be restarted, and you must configure it not to sleep — it's a young product versus a plain VM.
- **Durable Objects alarms or Workers Cron Triggers could replace the schedulers**, but that means refactoring the app into Workers-shaped code — a rewrite, not a migration; not recommended just to fit the platform.
- **Postgres must live elsewhere regardless** (Neon/Supabase/RDS/PlanetScale-PG); Hyperdrive then adds free pooling/caching from Cloudflare's edge, which mitigates but does not remove the external dependency.
- **The pragmatic hybrid:** small VM elsewhere (Hetzner/Lightsail/DO droplet) running Express + Postgres, fronted by Cloudflare Free (proxied DNS, Universal SSL, CDN, WAF, unmetered DDoS — all $0), with **user photos on R2** served via custom domain. R2's zero egress fee is the standout cost lever: photo bandwidth is free forever, versus $0.08–0.12/GB at the big clouds.
- **Net verdict:** use Cloudflare as the free edge (TLS/CDN/WAF/DNS) plus R2 for photos in nearly any architecture; treat Containers as a viable but bleeding-edge option for the API itself; do not plan on Cloudflare for Postgres.
