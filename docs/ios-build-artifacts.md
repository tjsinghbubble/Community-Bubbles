# iOS Build Artifacts

Generated by `npm run mobile:build:ios-sim` (or `npm run ios` from `mobile/`)
→ `preios` + `expo run:ios --no-bundler` + `postios`

The iOS build has two distinct phases with different file locations:
1. **`expo prebuild` + `pod install`** — generates `mobile/ios/` (once, or after SDK changes)
2. **Xcode compilation** — writes everything to `~/Library/Developer/Xcode/DerivedData/`

No JS bundle files are written to disk. `--no-bundler` means the running Metro
dev server serves the JS bundle over the network.

---

## Phase 1 — `mobile/ios/` (generated project, inside iCloud scope)

This directory is created by `expo prebuild` and populated by `pod install`.
It is **not** transient per-build — it persists between builds and is only
regenerated after `expo prebuild` is re-run (SDK upgrades, plugin changes).
It is large (~2 GB with Pods) and should be excluded from iCloud and
Time Machine.

### `Pods/` — CocoaPods installed source

CocoaPods installs the full source of every native dependency here.
This is the dominant contributor to directory count and file count.

| Extension | What it is |
|---|---|
| `.h`, `.hpp` | C/C++ and Objective-C headers (~8,500 files) |
| `.m` | Objective-C source files (~308) |
| `.mm` | Objective-C++ source files |
| `.c`, `.cpp` | C/C++ source files |
| `.swift` | Swift source files |
| `.S`, `.asm` | Assembly source files |
| `.xcconfig` | Xcode build configuration files (~222) |
| `.xcscheme` | Xcode scheme files |
| `.plist` | Property lists (Info.plist, entitlements, etc.) |
| `.pbxproj` | Xcode project file |
| `.xcworkspacedata` | Xcode workspace descriptor |
| `.modulemap` | Clang module map files |
| `.pch` | Precompiled header source files |
| `.xcprivacy` | Apple privacy manifest files |
| `.xcfilelist` | Xcode file lists for build phases |
| `.podspec` | CocoaPods spec files |
| `.in`, `.meson`, `.am` | Build system input files (autoconf, Meson) |
| `.sh` | Shell scripts for build phases |
| `.gz` | Compressed source archives |
| `.md`, `.markdown` | Readme files inside pod sources |
| `.json` | Metadata, package descriptors |
| `.build` | Build descriptor files |
| `.framework`, `.xcframework` | Pre-built frameworks (Hermes, ReactNativeDependencies) |
| *(code signing)* | `bundle/_CodeSignature/CodeSignature`, `CodeResources`, `CodeDirectory`, etc. |

### `build/` — staged headers for compilation

A small directory of source files copied out of Pods for the Xcode build.

| Extension | What it is |
|---|---|
| `.h`, `.cpp`, `.mm` | Headers and source staged for Xcode compilation |
| `.podspec`, `.swift`, `.json` | Metadata |

### `.expo/` — Expo build logs and state

| File | What it is |
|---|---|
| `xcodebuild.log` | Full stdout of the Xcode build (grows large, overwritten each build) |
| `xcodebuild-error.log` | Xcode error output |
| `devices.json` | Simulator/device state used by Expo CLI |
| `prebuild/cached-packages.json` | Expo prebuild package cache manifest |

## Phase 2 — `~/Library/Developer/Xcode/DerivedData/Bubble-*/` (outside iCloud scope)

This is where all actual compilation happens. Xcode never writes compiled
output into the project directory. The directory name includes a hash
(`Bubble-gxheibydasmrqwerwaqoeqlkqtdj`) that is stable per project.

### Clang compilation

| Extension | What it is |
|---|---|
| `.o` | Compiled object files (~1,554) |
| `.d` | Clang dependency files — one per `.o`, tracking `#include` inputs (~2,575) |
| `.dia` | Clang diagnostic files — serialized warnings/errors per TU (~2,586) |
| `.scan` | Static analyzer result files (~1,850) |
| `.pcm` | Precompiled Clang modules (~1,228) |
| `.pch-…` | Precompiled headers (hash-suffixed filenames) |
| `.hmap` | Header map files — fast include-path lookup tables (~318) |
| `.a` | Static libraries linked from object files |

### Swift compilation

| Extension | What it is |
|---|---|
| `.swiftmodule` | Compiled Swift module (~42) |
| `.swiftdoc` | Swift documentation data (~42) |
| `.swiftsourceinfo` | Swift source location info for debugging (~42) |
| `.swiftdeps` | Swift incremental dependency graph (~238) |
| `.swiftconstvalues` | Swift constant value extraction results (~251) |
| `.priors` | Swift type-checker optimization history |
| `.SwiftFileList`, `.SwiftConstValuesFileList` | Xcode-generated input file lists for Swift tasks |

### Linking and packaging

| Extension | What it is |
|---|---|

### Build graph and diagnostics

| Extension | What it is |
|---|---|
| `.msgpack` | Xcode build graph serialized in MessagePack binary format |

## Outside the project — `~/Library/Caches/com.apple.dt.Xcode/`

Pre-built framework and dependency caches. Written once per SDK version,
reused across projects.

| Content | What it is |
|---|---|
| Compiled framework caches | Pre-built `.framework` and `.xcframework` caches for dependencies |
| Source package caches | Swift Package Manager downloaded source |

## Not present (because `--no-bundler`)

| Extension | Why absent |
|---|---|
| `.hbc` | Hermes bytecode — only written for release/archive builds where JS is bundled into the `.app` |
| `.jsbundle`, `.map` | Metro bundle output — served from the running Metro process in dev mode |

## Exclusion coverage notes

- **`mobile/ios/Pods/` and `mobile/ios/build/`**: covered by `flag-temp-files.sh`'s `apply_all_icloud "${PROJECT}/mobile/ios"` and by the Watchman trigger on `mobile/ios/**`. The Pods directory is the dominant iCloud concern — ~2 GB of source installed by CocoaPods.
- **`~/Library/Developer/Xcode/DerivedData/`**: covered by `flag-temp-files.sh`'s `apply_all_library` calls. Watchman does not watch this location (it is outside the project root). The `.d`, `.dia`, and `.scan` files are the highest-volume output (>6,000 files per build) and are the primary Spotlight indexing concern.
- **`~/Library/Caches/com.apple.dt.Xcode/`**: covered by `flag-temp-files.sh`.
- **`mobile/.expo/`**: covered by `flag-temp-files.sh` and by the Watchman trigger on `.expo/**`. The `xcodebuild.log` file is rewritten each build and is the most likely file to trigger an iCloud upload attempt if exclusions are not set.
