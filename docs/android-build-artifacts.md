# Android Build Artifacts

Generated by `npm run mobile:build:android-emu`
→ `npm --prefix mobile run android`
→ `preandroid` + `expo run:android --no-bundler` + `postandroid`

Build configuration: **New Architecture enabled**, **Hermes enabled**,
architectures: `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`.

No JS bundle files are written to disk. `--no-bundler` means the running Metro
dev server serves the JS bundle over the network; the APK connects to it at
runtime.

---

## Inside the project — `mobile/android/`

### `app/.cxx/` — NDK / CMake (New Architecture C++ compilation)

This directory is the largest single source of churn on incremental builds.
React Native's JSI bridge, Fabric renderer, and Turbo Module bindings are
compiled here for each ABI.

| Extension | What it is |
|---|---|
| `.o` | Compiled object files — one per translation unit per ABI (~400 total) |
| `.so` | Shared libraries built per ABI (~170 total); later merged into APK |
| `.a` | Static libraries |
| `.c`, `.cpp`, `.h` | Source/header copies staged for compilation |
| `.cmake` | CMake cache and configuration snapshots |
| `.ninja` | Ninja build graph files |
| `.ninja_deps`, `.ninja_log` | Ninja dependency tracking and build log |
| `.json` | CMake API response files (codemodel, cmakeFiles, cache query results) |
| `.log` | Compiler stdout/stderr |
| `.txt` | CMake-generated text outputs |
| `.verify_globs`, `.check_cache` | Incremental validation sentinels |
| *(extensionless)* | CMake API query files: `codemodel-v2`, `cmakeFiles-v1`, `cache-v2` |

### `app/build/intermediates/` — Gradle / AGP compilation

| Extension | What it is |
|---|---|
| `.class` | Compiled Java/Kotlin bytecode (pre-dex stage) |
| `.kotlin_module` | Kotlin metadata for incremental compilation |
| `.java` | Generated sources: `BuildConfig.java`, `R.java`, annotation processor output |

| `.flat` | AAPT2 compiled resource files (~245); one per resource XML or image |
| `.xml` | Merged `AndroidManifest.xml`, merged resource files |
| `.ap_` | AAPT2 linked resource package |
| `.webp`, `.png` | Compiled and merged image resources |
| `.so` | Native libraries merged from AAR dependencies |
| `.bin` | Serialized Gradle data structures (task state, dependency graphs) |
| `.len`, `.at`, `.tab`, `.tab_i`, `.keystream` | Gradle incremental task journal files |
| `.check_cache` | Gradle up-to-date check sentinels |
| `.log`, `.txt`, `.json`, `.properties` | Build metadata, task output, manifests |
| `.sha` | Input/output checksums used by Gradle for incremental builds |
| `.lock` | Gradle file locks |
| *(extensionless)* | `zip-cache/` entries (base64-named content hashes), `merge-state` |

## Outside the project — `~/.gradle/caches/`

Written during dependency resolution on the first build; served from cache on
subsequent builds. The Watchman trigger does not cover this location.

| Extension | What it is |
|---|---|
| *(extensionless)* | Content-addressed build cache entries under `build-cache-1/` — thousands of files |
| `.jar`, `.aar` | Downloaded dependency archives |
| `.pom`, `.module` | Maven / Gradle dependency metadata |
| `.class`, `.kt`, `.hpp`, `.h`, `.cpp` | Source and class files extracted from dependency JARs for transforms |
| `.bin` | Serialized transform outputs and dependency resolution results |
| `.marker`, `.receipt` | Cache validity markers |
| `.kotlin_module` | Kotlin module metadata from dependency artifacts |
| `.flat` | AAPT2 compiled resources extracted from AAR dependencies |
| `.xml`, `.json`, `.properties`, `.txt` | Metadata from AAR manifests and Gradle module descriptors |
| `.zip` | Archived transform inputs/outputs |
| `.lock`, `inject-1` | Gradle daemon and inter-process coordination |
| `.png` | Image resources extracted from AARs |

## Not present (because `--no-bundler`)

| Extension | Why absent |
|---|---|
| `.hbc` | Hermes bytecode — only written when JS is bundled into the APK for release builds |
| `.bundle`, `.map` | Metro bundle output — served from the running Metro process, never written to disk in dev mode |

## Exclusion coverage notes

- **`app/.cxx/` and `app/build/`**: covered by the Watchman trigger (`mobile/android/**`). The `.metadata_never_index` sentinel placed in each new directory at creation time protects all files created inside it from Spotlight. iCloud and Time Machine exclusions are applied per-directory by the handler.
- **`~/.gradle/caches/`**: covered by `flag-temp-files.sh` at pre/post build time, but not by Watchman. On a first build (cache miss), new files arrive in `~/.gradle/caches/` before `postandroid` can re-flag the directory.
- **No JS files**: the entire Metro transform / bundle cache lives in `$TMPDIR` (`/var/folders/…`), which is outside iCloud Drive scope entirely and requires no exclusion management.
